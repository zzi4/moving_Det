# 航拍视频运动目标 OBB 检测与跟踪系统设计

日期：2026-08-03  
状态：总体方向已确认，等待书面设计审阅

## 1. 背景与目标

本项目面向悬停或已稳定的航拍视频，检测并跟踪交通参与者。视频分辨率为
3840×2160、帧率为 30 FPS，最终场景中的典型小目标约为 20×40 像素。系统不采用
“每帧独立检测后再关联”的纯 tracking-by-detection 方案，而是把相邻帧中的运动变化
作为目标发现和定位的核心证据。

系统只要求运动目标触发新轨迹。目标一旦被发现，就由跟踪状态、局部外观和离线全局
关联维持；短暂停止或弱运动不能导致轨迹立即消失。所有空间输出均使用旋转目标框
（OBB），后续类别识别沿整条轨迹聚合多帧信息完成。

完整系统的处理链路为：

```text
稳定航拍视频
  → 残余运动补偿
  → 多时间尺度运动证据
  → 类别无关 OBB 候选或检测
  → 离线 OBB 轨迹关联与补全
  → 轨迹级交通参与者分类
```

## 2. 当前数据

现有验证数据位于：

```text
/mnt/nas/Processing_data/mot_sequence/
├── motorway_fml_json_v1/   # 300 帧
└── motorway_sequence2/     # 160 帧
```

每帧均包含一张 3840×2160 JPG 和一个同名 Labelme 风格 JSON。目标标注使用
`shape_type="rotation"`、四个顶点、`direction` 弧度和 `group_id` Track ID。
`motorway_sequence2` 还包含 `label="ignored"` 的多边形忽略区域；这些多边形不是
OBB，也不参与正负样本统计。

只读统计结果如下：

| 序列 | 帧数 | 目标标注 | 轨迹数 | OBB 长边中位数 | OBB 短边中位数 | 相邻帧中心位移中位数 |
|---|---:|---:|---:|---:|---:|---:|
| motorway_fml_json_v1 | 300 | car 60,860；truck 1,089 | 252 | 62.40 px | 26.48 px | 2.50 px |
| motorway_sequence2 | 160 | car 10,506；truck 423；two_wheeler 60 | 82 | 64.56 px | 25.37 px | 6.86 px |

第一段序列约有 30% 的轨迹相邻帧中心位移中位数低于 0.5 像素，可用于验证静止或
低速目标不会被错误当成新运动目标。第二段序列中的目标基本持续运动。

当前数据目标尺寸中位数约为 64×26 像素，大于最终的 40×20 像素级目标，因此当前
数据只能验证标注解析、运动证据、OBB 生成和轨迹逻辑，不能单独证明最终小目标性能。
论证实验同时加入 0.7 倍等比例降采样组，使目标中位尺寸约为 45×18 像素，作为接近
最终尺度的退化测试；最终结论仍需真实小目标序列验证。

## 3. 范围

### 3.1 第一阶段：无需训练的论证实验

第一阶段验证以下假设：

1. 固定或稳定背景下，多时间尺度运动证据能以较高召回率覆盖移动目标。
2. 多帧融合优于单一相邻帧差和传统背景减除。
3. 运动候选可以形成连续 tubelet，并提供合理的初始 OBB。
4. 降采样到接近最终目标尺寸后，性能下降仍可量化且不过度失控。

第一阶段不训练深度网络，不进行最终类别判定，也不以实时速度为目标。

### 3.2 第二阶段：运动引导的类别无关 OBB 检测器

若第一阶段验证通过，训练 RGB 与运动信息双分支检测器，使用当前帧外观修正运动候选
的位置、尺寸和车身方向。检测器只输出“运动交通目标”及 OBB，不在此阶段区分类别。

### 3.3 第三阶段：离线轨迹与轨迹级分类

在 OBB 检测基础上完成离线全局关联、漏检补全和停止状态保持，再对每条完整轨迹抽取
多个高质量旋转裁剪，聚合分类为 car、truck、two_wheeler、pedestrian 等类别。

三个阶段分别设置实现门槛，不放入同一个实施计划。本次设计审阅通过后，只为第一阶段
编写实施计划和代码。第二阶段必须等待第一阶段指标确认后再单独规划；第三阶段必须等待
类别无关 OBB 检测结果稳定后再单独规划。

## 4. 统一数据模型与坐标约定

系统内部使用以下核心对象：

```text
FrameSample:
  sequence_id, frame_index, timestamp, image_path

OBB:
  cx, cy, width, height, theta

Annotation:
  obb, class_name, track_id, difficult

MotionEvidence:
  short_diff, medium_diff, long_diff, background_diff, fused_score

Proposal:
  frame_index, obb, motion_score, source_component_id

Track:
  track_id, ordered states, lifecycle state, appearance summary
```

内部 OBB 统一为长边定义：

```text
width >= height
theta ∈ [-π/2, π/2)
```

角度表示矩形长轴，不区分车头与车尾，因此 `theta` 和 `theta + π` 等价。角度比较、
损失和平滑全部使用 π 周期，不能直接对原始角度做普通 L1。Labelme 四点框进入系统时
重新计算中心、长短边和规范角度；原始 `direction` 作为附加字段保留，用于审计但不
直接视为唯一真值。输出四点按顺时针排序。

Track ID 优先读取 `group_id`。`description` 中的数字或 `tid=N` 只用于一致性校验，
不能静默覆盖冲突的 `group_id`。

## 5. 第一阶段运动证据设计

### 5.1 支持帧窗口

中心帧为 `I_t`，离线窗口默认使用前后各 15 帧，即 31 帧、约 1.03 秒。边界处只使用
实际存在的支持帧，不复制首尾帧。时间间隔固定为：

```text
k ∈ {1, 3, 7, 15}
```

该设置同时覆盖约 33 ms、100 ms、233 ms 和 500 ms 的运动变化。

### 5.2 残余配准

尽管输入已做视频稳定，仍在四分之一分辨率灰度图上估计支持帧到中心帧的全局欧氏
变换（平移与旋转），再以原分辨率变换参数进行重采样。估计使用 ECC；若 ECC 不收敛、
相关系数低于 0.8，或估计变换超过 20 像素平移/2 度旋转，则记录告警并退回单位变换。

忽略多边形和上一轮高置信运动区域不参与第二轮配准，以免大量车辆影响背景对齐。

### 5.3 多尺度运动通道

对配准后的灰度帧计算：

```text
D_k(t) = max(|I_t - I_(t-k)|, |I_t - I_(t+k)|)
B_t    = temporal_median(I_(t-15) ... I_(t+15))
D_bg   = |I_t - B_t|
```

缺少前向或后向支持帧时使用可用的一侧。每个通道用中位数绝对偏差（MAD）计算鲁棒
Z 分数：

```text
Z = max(delta - median(delta), 0) / max(1.4826 * MAD(delta), 2.0)
```

其中分母的 2.0 是 8 位灰度图噪声下限。用于阈值判断的 Z 分数截断到 `[0, 6]`；
用于保存和可视化的归一化分数为 `Z / 6`，范围为 `[0, 1]`。默认融合为：

```text
Z_t = max(Z_1, Z_3, Z_7, Z_15, Z_bg)
M_t = Z_t / 6
```

不在首轮实现中把光流作为必需依赖。稠密光流只作为后续消融项，因为固定背景下帧差和
时域背景更简单，而小纹理目标上的光流本身可能不稳定。

### 5.4 运动掩码与时空候选

运动阈值不只采用单一手工值。校准序列上比较 MAD 倍数 `{3, 4, 5, 6}`。参数选择规则
固定为：在每 100 个移动 GT 不超过 25 个误候选的约束下，最大化
`Recall@rIoU 0.25`；召回相同时选择误候选更少的配置。如果没有配置满足误候选约束，
选择误候选最少的配置，并把第一阶段门槛标记为未通过。选定配置冻结后在第二段序列上
评估。

二值掩码只做 3×3 闭运算和小孔填充，不做可能抹除小目标的大核开运算。面积小于
4 像素的孤立连通域被移除。候选必须在连续 3 帧中至少有 2 帧获得空间邻近的运动
响应，以抑制单帧压缩噪声。

相邻运动块先在 `(x, y, t)` 空间连接成短 tubelet，再基于 tubelet 的时域联合区域
生成 OBB。OBB 使用最小面积矩形，但四边向外扩展 25%，用于补偿运动掩码只覆盖车身
边缘或形成双边拖影的情况。该 OBB 只是高召回候选，不被当作最终车身方向。

`ignored` 多边形内的运动响应不生成误报；候选中心位于忽略区内，或候选与忽略区重叠
超过 50% 时，从评估中排除。

## 6. 第一阶段对照实验

使用 `motorway_fml_json_v1` 校准参数，冻结后在 `motorway_sequence2` 评估。每种
方法同时在原始分辨率与 0.7 倍降采样组运行。

主要验收指标只统计中心帧前后均具备 15 帧支持的核心区间，即帧
`16 ... (N-15)`；首尾边界帧仍生成结果并单独报告，但不用于通过/失败判断。MOG2 在
校准和测试序列的前 60 帧只更新背景模型，之后从序列首帧重新运行并生成全段结果，
从而避免不同初始化状态影响核心区间比较。该离线预热与其他方法使用未来支持帧的设定
一致。

对照组为：

1. 单帧间隔帧差：`|I_t - I_(t-1)|`。
2. MOG2 背景减除；`history=60`、关闭阴影检测，并在校准序列比较
   `varThreshold ∈ {9, 16, 25}`。
3. 31 帧时域中值背景差。
4. 多时间尺度融合，但不做三维 tubelet。
5. 完整多时间尺度融合与三维 tubelet。

移动 GT 的默认定义是同一 Track ID 在 5 帧内中心位移不小于 3 像素。额外报告
2、5 像素阈值下的敏感性结果，避免单一运动阈值掩盖慢速目标表现。

指标包括：

```text
Motion-mask coverage:
  GT OBB 中被运动掩码覆盖的面积比例

Proposal recall:
  Recall@rotated-IoU 0.25
  Recall@rotated-IoU 0.50
  Center-in-GT recall

False positives:
  每帧误候选数
  每 100 个 GT 的误候选数

Temporal metrics:
  每条轨迹首次发现延迟
  移动帧轨迹覆盖率
  每条 GT 轨迹产生的额外碎片数
```

所有指标按目标长边、短边、面积和运动速度分层报告。

第一阶段进入深度模型阶段的门槛为：

1. 完整融合方法在固定误候选率下，`Recall@rIoU 0.25` 比最佳单一基线提高至少
   5 个百分点。
2. 原始分辨率 `Center-in-GT recall` 不低于 95%，`Recall@rIoU 0.25` 不低于 90%。
3. 0.7 倍降采样组的 `Recall@rIoU 0.25` 相比原始分辨率下降不超过 10 个百分点。
4. 移动帧轨迹覆盖率不低于 90%，平均额外碎片不超过每条 GT 轨迹 0.2 个。

若未达到门槛，实验仍视为有效论证结果，但不能直接进入大规模模型训练；应根据分尺寸
和分速度结果判断问题来自运动证据、OBB 拟合还是时空连接。

## 7. 第二阶段双分支 OBB 检测器

### 7.1 4K 切片

运动图始终在原始分辨率计算。训练与检测使用 1024×1024 切片，水平和垂直重叠
256 像素。运动区域向四周膨胀 128 像素后决定需要处理的切片。

训练期间，所有包含 GT OBB 的切片无条件保留，不能因为运动响应弱而丢弃正样本；
另采样高运动无目标切片作为困难负样本。推理时，运动门控只控制“新轨迹发现”切片，
已有轨迹附近的切片由跟踪器强制保留。

### 7.2 网络结构

网络包含：

```text
RGB 分支:
  当前中心帧，预训练二维 backbone，输出 P2-P5

Motion 分支:
  D_1, D_3, D_7, D_15, D_bg 五通道
  使用浅层卷积编码器，输出与 P2-P5 对齐的特征

融合:
  每个尺度使用可学习门控残差融合
  F_rgb + sigmoid(G(F_rgb, F_motion)) * F_motion

OBB Head:
  objectness
  cx, cy, width, height
  cos(2θ), sin(2θ)
```

保留 P2 是因为最终目标约为 20×40 像素。第一版检测头为类别无关单类头，类别标签仅
用于后续分类，不进入检测损失。

框回归由旋转 IoU 与 KLD/GWD 类损失组成；目标置信度使用 Varifocal 或 Focal Loss。
切片结果回到全图坐标后使用 rotated IoU NMS 合并，不能使用水平框 NMS。

### 7.3 时序监督

同一 Track ID 在相邻中心帧上的预测用于时序一致性损失，但只约束中心速度、尺寸变化
和 π 周期角度变化，不强制目标匀速。该损失是辅助项，不能替代每帧 GT OBB 监督。

## 8. 离线 OBB 跟踪

每条轨迹状态为：

```text
(cx, cy, width, height, theta, vx, vy, angular_velocity)
```

新轨迹必须在 5 帧内至少 2 次获得运动引导 OBB 才能确认。已有轨迹即使暂时没有
运动响应，也继续在预测位置运行 RGB OBB 修正，不要求重新通过运动门限。

候选间关联代价为：

```text
C =
  λ1 * (1 - rotated_IoU)
  + λ2 * normalized_center_distance
  + λ3 * appearance_distance
  + λ4 * periodic_angle_distance
  + λ5 * velocity_residual
```

短期使用卡尔曼或交互多模型状态预测；离线阶段再用最小费用流或等价的全局图优化修复
局部错误。目标连续 90 帧没有可靠 OBB 修正，且预测位置不再获得外观支持时终止；
预测中心离开图像有效区域时立即终止。被遮挡或停止的轨迹允许跨越不超过 90 帧的空缺
后重新连接。

跟踪输出保留每帧 OBB、置信度、运动状态和统一 Track ID。矩形角度只表达车身长轴；
行驶方向由轨迹速度确定，车头/车尾方向不由 OBB 单独推断。

## 9. 轨迹级分类

分类器从每条轨迹选择最多 8 帧，优先选择目标面积较大、清晰度高、遮挡少且时间分布
均匀的帧。每帧按 OBB 旋转校正，并扩展到原框 2 倍上下文后裁剪。多帧特征通过注意力
或质量加权平均聚合，输出整条轨迹类别。

轨迹级分类结果回填到所有帧，但保留帧级置信度和轨迹级置信度，便于排查类别随时间
不稳定的问题。

原始数据目录只读。所有实验输出写入项目下：

```text
runs/<experiment-name>/
├── config.yaml
├── metrics.json
├── per_frame.csv

```

每次运行记录输入序列、Git commit、随机种子、参数、软件版本和处理分辨率。阈值校准

## 11. 错误处理

1. JPG 或 JSON 缺失：数据索引阶段报错并停止，不静默跳帧。
2. OBB 非四点、点坐标越界或 `group_id` 缺失：记录具体文件与 shape 序号并停止。
3. `ignored` 多边形允许任意三个以上顶点，不套用 OBB 校验。
4. ECC 失败：记录质量和变换，退回单位变换，实验汇总中报告失败比例。
5. 支持帧不足：使用现存帧并记录实际窗口长度。
6. 空运动掩码：输出合法空候选，不复用上一帧候选冒充检测。
7. OBB 角度跨边界：先按 π 周期规范化再计算误差和插值。

## 12. 测试策略

单元测试至少覆盖：

1. Labelme 四点框与规范 OBB 的双向转换。
2. `theta` 与 `theta + π` 等价、角度边界连续。
3. rotated IoU、忽略区重叠和切片坐标回映。
4. Track ID 解析与跨帧一致性检查。
5. 合成平移背景下的 ECC 配准。
6. 合成移动矩形的多尺度运动掩码和 tubelet 连接。
7. 目标停止、恢复运动和离开边界时的轨迹生命周期。

集成测试使用连续 10 帧验证：

```text
数据加载 → 运动图 → 候选 OBB → 时空连接 → 指标 → 可视化
```

完整论证实验必须能够从固定配置一次性重跑，并生成同结构的指标与覆盖图。

## 13. 已知风险

1. 当前序列总计只有 460 帧，场景单一，不能代表 4 小时数据的光照和背景变化。
2. 当前目标约为 64×26 像素，0.7 倍降采样只能近似真实小目标，不能替代真实数据。
3. 树叶、阴影、压缩噪声和残余抖动可能产生强运动伪响应。
4. 运动掩码的方向通常是速度方向，不等于车辆 OBB 长轴方向。
5. 静止车辆不会启动新轨迹；这是已确认的产品定义，而不是漏检修复目标。
6. 对已有轨迹的停止状态保持依赖跟踪器和 RGB 修正，不能只依赖运动候选。
